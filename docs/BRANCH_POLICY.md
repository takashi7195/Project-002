# 安定版と開発版の運用ルール

## 目的
このドキュメントは、プロジェクトの「安定版」と「開発版」の意味と運用方法を明確に定義し、次の作業者が迷わず作業を継続できるようにするための資料である。

## 基本方針
- main は「安定版」として扱う。
- develop は「開発版」として扱う。
- 安定版は、動作確認が完了した状態だけを置く。
- 開発版は、試験的な改善や新しいアイデアを試すためのブランチとする。
- どちらがどの役割を持つかは、作業開始時に明確に確認する。

## 安定版（main）
安定版とは、次の条件を満たす状態を指す。
- 既知の不具合が確認されていない、または許容できる範囲に収まっている
- 主要機能が正常に動作している
- 公開前または公開中の状態として扱ってよい
- 次の作業者がそのまま確認・利用できる状態である

### 安定版で行うこと
- 重要な保存ポイントの記録
- 公開可能な状態の保持
- リリース候補の確認
- 既存機能の維持

### 安定版で避けること
- 試験的な変更の混入
- 実験用コードの残置
- 完了していない機能の反映

## 開発版（develop）
開発版とは、次の条件を満たす状態を指す。
- 新機能や改善案を試すための作業場所である
- 完成していない部分が含まれる可能性がある
- 動作確認が必要であり、安定版へ反映する前に検証を行う
- 実験的な変更を自由に試してよいが、原則として履歴に残す

### 開発版で行うこと
- UIの改善案の検証
- ロジックの修正試験
- 新しい演出や機能の実装
- 変更理由と効果を HISTORY.md に記録する

### 開発版で避けること
- 安定版の動作を破壊する変更をそのまま入れること
- 作業途中の未確認コードを安定版へマージすること
- 実験結果を記録せずに放置すること

## ブランチ運用
- main: 安定版
- develop: 開発版
- feature/xxx: 機能単位の作業用
- fix/xxx: 不具合修正用

## ルール
- どのブランチが現在の作業対象かを明確にする。
- 重要な変更は、HISTORY.md に日付付きで詳細を追記する。
- 作業の結果が安定版に反映可能かどうかを確認してからマージする。
- 安定版に反映した時点で、履歴に「安定版更新」または「リリース」記録を残す。

## 用語の定義
### 安定版
現在のプロジェクトとして利用・公開できる状態。大きな破壊的変更が入っておらず、既存動作が維持されている。

### 開発版
新しい改善や試験中の状態。動作確認と検証が必要であり、安定版に昇格する前に調整される。

### 追記記録
HISTORY.md に残す変更の記録。過去の記載を消さず、新しい日付で追加する。

## 日付の記載ルール
- 日付は必ず YYYY-MM-DD HH:MM 形式で記載する。
- 例: 2026-09-02 10:30
- ブランチの役割変更、安定版保存、開発開始、修正、テスト結果などはすべて記録する。

## まとめ
- main は安定版。
- develop は開発版。
- 重要な判断や変更は HISTORY.md に日付付きで追記する。
- 安定版と開発版の役割を混同しないことが、継続開発の基本である。
